# PgRest 0.2 — Phase 1: Foundations, Safety, Grammar, Single-Statement Reads — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace PgRest 0.1's ad-hoc parser and preload-based reads with a PostgREST-grammar parser, a relationship planner and a single-statement SQL compiler; fix every P0 safety bug; and stand up a compatibility harness that compares PgRest against a real PostgREST container.

**Architecture:** Request → `PgRest.Request` (ordered query params, parsed headers) → grammar (NimbleParsec) → AST → `PgRest.Planner` (resolves embeds against `PgRest.SchemaGraph` built from Ecto resources, validates columns, applies `scope/2` at every node) → `PgRest.SQL.*` (one parameterized statement, JSON built in Postgres, Ecto-scoped base queries spliced in as subqueries) → `PgRest.Executor` (transaction, `tx=rollback`) → `PgRest.Responder`. Golden scenarios recorded from PostgREST v14 are the source of truth.

**Tech Stack:** Elixir 1.19 / OTP 28, Ecto 3.14, Ecto SQL 3.14, Postgrex 0.22, Plug 1.20, NimbleParsec (new dep, `runtime: false`), StreamData (new test dep), Req (new test dep), Docker Compose (Postgres 16 + PostgREST v14).

## Global Constraints

- **Drop-in parity governs:** a supabase-js app must just work. Transport details (`Server`, `Date`, header order/casing, chunking) are not compared. Semantic headers compared: `Content-Range`, `Content-Type`, `Preference-Applied`, `Location`, `Content-Location`, `Content-Profile`, `Allow`, `Range-Unit`.
- Comparison target: `postgrest/postgrest:v14.<latest patch>` — look up the newest v14 tag on Docker Hub once and pin the exact tag in `docker-compose.yml`.
- PgRest-only concepts fail like their Postgres equivalents (scope ⇒ RLS: 42501; unknown column ⇒ 42703 / PGRST204; etc.). **The recorded PostgREST response is authoritative** for status, code, message, details, hint.
- Ecto schemas registered as resources are the contract. Phase 1 never discovers tables from the database. `PgRest.Catalog` reads only metadata about registered tables (column types, column defaults) and never exposes it.
- **Security audit.** This plan applies every Phase 1 item of the 2026-11-14 security/performance audit and its resolutions file (`…/scratchpad/fable-security-perf-audit.md`, `…/scratchpad/fable-audit-resolutions.md`). Finding ids (S-H1, P-H3, …) are cited next to each fix. The names and defaults below are shared with the Phase 2 and Phase 3 plans, so do not rename them.
- One SQL statement per read. No per-row or per-embed queries.
- `require_filters_for_mutations` plug option defaults to `true` (Supabase `pg-safeupdate` parity: SQLSTATE `21000`, message `DELETE requires a WHERE clause` / `UPDATE requires a WHERE clause`, HTTP 400). Differential runner sets it `false`.
- Breaking changes are fine (0.2). Remove: `/:resource/:id` routes, `?not.col=` negation key form, `{"error": …}` bodies. Keep `is.not_null` (PostgREST v13+ supports it).
- `mix quality` must pass at the end of every task (compile --warnings-as-errors, format, sobelow, ex_dna, doctor, credo --strict, dialyzer).
- **Git:** never run `git commit`, `git push`, `git tag`, `git add` or anything that changes the index or HEAD, and never `mix hex.publish`. The maintainer stages and commits. A "Suggest a commit message" step means: leave the work in the working tree and propose a message (no AI attribution); the maintainer decides if and when to commit.
- **Every implementer and reviewer agent loads the `elixir-genius` skill (Skill tool) before writing or reviewing code**, plus `elixir-phoenix-guide:elixir-essentials`; `elixir-phoenix-guide:ecto-essentials` for Ecto/SQL work; `elixir-phoenix-guide:testing-essentials` for tests.
- **Subagent models:** implementers `sonnet`; spec/code reviewers and final branch review `opus`; mechanical search/replace `haiku`. Never `fable` (reserved for the separate security/performance audit of the plans).
- Idiomatic Elixir: `with` over nested `case`; function-head matching over conditionals; predicates end in `?` (no `is_` prefix outside guards); module-level `alias`/`import` only; no process dictionary; `Req` for HTTP; `Jason` for JSON.
- **Never create atoms from request input.** Columns, relations and aliases are resolved by string lookup in `__pgrest_config__` maps (`field_sources`, graph); unknown names become PostgREST errors, not `ArgumentError`.
- Version stays `0.1.0` until the Phase 3 release task.

Override with `PGREST_DB_PORT`, `PGREST_POSTGREST_URL`, `PGREST_POSTGREST_LIMITS_URL`. **Every published port binds `127.0.0.1:<p>:<p>`** (S-M5).
- **Bind parameters:** request-derived values are bound as text and cast in SQL (`$n::text::<pgtype>`), because Postgrex picks the encoder from the cast and rejects `"1"` for `$n::integer`. JSON payloads are bound once as `$n::text::json`. Values produced in Elixir by `Ecto.Type.dump/2` are bound natively. `PgRest.SQL.Builder.param/4` takes `mode: :text | :native`.
  - **`<pgtype>` is the column's catalog type** (P-H3): `PgRest.Catalog.column_types(repo, schema, table) :: %{String.t() => String.t()}`, from `format_type(atttypid, atttypmod)`, lazily cached like `column_defaults/3`. Filter and payload casts use `$n::text::<catalog type>`. The Ecto type mapping is only a fallback when the catalog is unavailable. Catalog type text comes from `pg_catalog`, never from the request.
  - **`LIMIT` and `OFFSET` are bind parameters** at every node (P-H1), so paging does not multiply SQL texts.
- **SQL emission rules** (S-H2, S-M6). Request text reaches SQL only as a bind parameter or through one of these `PgRest.SQL.Builder` functions:
  - `ident/1` quotes identifiers and **rejects NUL bytes** (raises `ArgumentError`). The grammar rejects NUL in identifiers first, so a request with `%00` gets a 400, never a raise.
  - `cast(expr_iodata, type :: String.t()) :: iodata` re-validates `^[A-Za-z_][A-Za-z0-9_ $]*(\[\])?$` with a 63-byte maximum and emits `CAST(<expr> AS <type>)`. The select/order grammar applies the same restriction, so a bad cast is a 400 at parse.
  - **JSON-path keys are always bind parameters**, never quoted literals.
  - The fts config stays bound (`$n::text::regconfig`).
  - **`$n` renumbering** of spliced Ecto SQL is done by a real tokenizer (`PgRest.SQL.Placeholders`) that understands doubled quotes, `E''` strings, `$tag$` quoting, `--` and `/* */` comments, and quoted identifiers. It asserts that the placeholder count equals `length(params)` and raises otherwise.
  - Logic-tree depth is capped at 16 in the grammar (S-H4).
- **Repo calls** (S-M3): every PgRest repo call passes `log: false` and `telemetry_options: [pgrest: true]`. PgRest's own `[:pgrest, :query]` span replaces the repo's query log. Bind values never appear in PgRest telemetry or logs.
- **Plug options and resource limits** (S-H4, S-L2, P-H1). Task 11 owns the full list; earlier tasks read the same keys with the same defaults:

  | Option | Default | Effect |
  |---|---|---|
  | `max_limit` | `nil` | clamps the root **and every embed lateral**, via `LEAST` |
  | `max_embed_depth` | `8` | deeper select trees → 400 `PGRST100`-shaped error, message `"embedding depth exceeds 8"` |
  | `max_body_bytes` | `8_000_000` | larger bodies → 413 |
  | `max_bulk_rows` | `10_000` | more rows in one write payload → 413 |
  | `count_modes` | `[:exact, :planned, :estimated]` | a `Prefer: count=` mode outside the list → 400 |
  | `tx_end` | `:commit` | `:commit_allow_override` honours `Prefer: tx=`; under `:commit`, `tx=` is ignored and not echoed (upstream `db-tx-end`). Compat routers set `:commit_allow_override`. |
  | `statement_cache` | `[promote_after: 3, max: 500]` | bounded named prepared statements (Task 11) |
  | `statement_timeout` | `nil` | when set, applied with `set_config('statement_timeout', $n, true)` in a setup statement in transactional requests, and the repo call's `timeout:` is set slightly above it; for non-transactional reads the docs recommend a dedicated repo with `parameters: [statement_timeout: …]` |

  413 bodies are `PgRest.Error`s with code `54000` (Postgres `program_limit_exceeded`), PgRest-only scenarios.
- **Error details are scrubbed off the identity scope** (S-H5): `PgRest.Error.Translate.from_exception/3` takes `scrub_details?: boolean()`. It is true when the request's effective source is not the identity scope, or when any column allowlist (`readable:`/`writable:`) is not `:all`. When true, `details` is `nil` for SQLSTATE 23502, 23503, 23505, 23514 and 23P01, as Postgres does under RLS.
- **Column exposure** (S-M2): resource options `readable: [atom] | :all` and `writable: [atom] | :all`, both default `:all`, are enforced on the 42501 path. `__schema__(:redact_fields)` are hidden for read, filter and order unless listed in `readable:`. The default changeset casts the `writable` fields minus `redact_fields`.
- **Compose is a test harness only** (S-M5): ports bind `127.0.0.1`, no `restart: unless-stopped`, the compose file and its README section are headed "test harness only", and user-facing docs never show a superuser anon role, passwords or JWT secrets.
- **`scope/2` is a predicate contract:** it may add `where`, `join` and `distinct` only. `limit`, `offset`, `order_by`, `group_by`, `select` or preloads in a scope query raise `ArgumentError` naming the resource on first use. Per-parent permission limits arrive in Phase 2 through the authorization hook.
- **Authorization is fail-closed per resource:** when `:authorization` is configured, `authorize(conn, resource, :read, context)` runs for **every** resource a request touches (root, each embed, m2m junction resources), not only the root. Writes also call it with their own operation on the target. **Writes need `:read` too** (S-H1): PATCH, DELETE, PUT and upsert with filters, `return=representation`, a count, or a `Location` header, and INSERT with `return=representation`, also call `authorize(conn, target, :read, ctx)`, because filters, counts and RETURNING are a read channel (Postgres requires `SELECT` for `WHERE` and `RETURNING`). Phase 2 extends the rule to `authorize_query/5`. Any `{:error, _}` denies the request as a Postgres privilege failure would: `42501`, 401 for the anonymous role, 403 otherwise (Phase 1 is always anonymous, so 401).

## Review Focus

1. **URL encoding from supabase-js** (`+` for space, `%2C`, `%28`, unicode in values) — must decode exactly like PostgREST. Test owned by Task 4.
2. **Same table embedded twice / self-reference with aliases** (`a:family_tree!parent(*),b:family_tree!child(*)`) — SQL aliases must not collide. Test owned by Task 10.
3. **`scope/2` with joins or forbidden clauses.** A scope that joins another table must not duplicate rows, so it is spliced as a PK semijoin. A scope using `limit`, `order_by` and the like raises a clear `ArgumentError`. Test owned by Task 8.
4. **Empty embeds** — to-one with no match is `null`, to-many is `[]`, `!inner` with no match drops the parent, spread of a null to-one yields `null` columns. Test owned by Task 10.
5. **Composite primary keys and large bulk inserts** (10 000 rows; must not hit the 65 535 bind-param limit; Location/write-check with composite PKs). Tests owned by Tasks 12 and 13.
6. **Writes as a read channel** (S-H1, S-H5, S-L2). A role allowed `:update` but not `:read` must not learn anything through filters, `return=representation`, counts or `Location`; constraint `details` must not leak hidden rows or columns off the identity scope; `tx=rollback` is honoured only under `tx_end: :commit_allow_override`. Tests owned by Tasks 3, 12, 13 and 14.
7. **Request text that reaches SQL** (S-H2, S-M6, P-H3). Casts only through `Builder.cast/2`, JSON keys always bound, NUL rejected, a real placeholder tokenizer, filter casts from catalog types. Tests owned by Tasks 5, 6, 8 and 9.
8. **Unbounded work per request** (S-H4, P-H1). Embed fan-out (`max_limit` on every lateral, `max_embed_depth`), logic depth, body and bulk size, count modes, statement timeout, and a statement cache that attacker-minted SQL texts cannot grow. Tests owned by Tasks 4, 5, 10, 11 and 12.
9. **Scoped-write hot paths** (P-H4, P-M1, P-M3, S-L1). Correlated `EXISTS` guards (never `IN (subquery)`), keys returned as one `json_agg` column, the effective source computed once per resource, scoped PATCH/DELETE rows taken `FOR UPDATE`, and the default-changeset insert fast path. Tests owned by Tasks 8, 12, 13 and 14.
